# wear-compose-cmp

**AndroidX Wear Compose, compiled for WebAssembly.**

A mechanical port of `androidx.wear.compose` — Material 3, Foundation and Material Core — from
Android to Compose Multiplatform, so that the Wear components can be rendered in a browser by the
[UI builder](https://github.com/yschimke/compose-preview-server) instead of only on a watch or an
emulator.

It is **generated, not forked**. Nothing here is a hand-maintained copy of AndroidX: the sources are
vendored from each release, transformed by rules, and patched only where a rule cannot reach. When
AndroidX cuts a release, the same pipeline runs again and the diff is the review.

```
upstream.json ──► tools/sync.py ──► upstream/ ──► tools/transform.py ──► modules/*/src/commonMain
   the pin        Google Maven      vendored        rules + patches         generated, committed
```

## What you get

| Artifact | Contents |
| --- | --- |
| `ee.schimke.wearcmp:wear-compose-material3` | 122 of 136 Material 3 files |
| `ee.schimke.wearcmp:wear-compose-foundation` | 65 of 69 Foundation files |
| `ee.schimke.wearcmp:wear-compose-material-core` | all 17 Material Core files |
| `ee.schimke.wearcmp:port-runtime` | the port's own seams — the `expect`s the three above compile against |

Targets: **wasmJs** (the point of the exercise) and **jvm** (which compiles an order of magnitude
faster and is how the port is checked). Version is `<upstream>-cmp<NN>` — `1.7.0-beta02-cmp01` is
the first port of AndroidX 1.7.0-beta02.

What is *not* in there, and why, is measured rather than described:
[`docs/ANDROID_SURFACE.md`](docs/ANDROID_SURFACE.md) is generated by the same run that produces the
sources. 18 files of 222, each with a reason: the two date/time pickers, dynamic colour, the
one-handed-gesture *indicators*, and the two dialogs whose icons are animated vector drawables.

**Curved text draws, and is not curved.** `basicCurvedText`, `curvedText`, `CurvedLayout` and
`TimeText` are all ported and render: each run is measured with the real font, then drawn as one
straight line, rotated to the tangent of its arc and centred on it. Short labels — a time, a title,
which is what Wear curves — read correctly; a long run visibly departs from the arc towards its
ends. The seam and the way out are in
[`CurvedTextDelegate`](modules/wear-compose-foundation/src/commonPort/kotlin/androidx/wear/compose/foundation/CurvedTextDelegate.kt),
which carries the TODO.

## Using it from a wasm app

The published artifacts live on the `wear-compose-cmp-maven` branch, which `raw.githubusercontent`
serves as a static Maven repository — **no credentials**, which matters because a consumer's CI
would otherwise need a token to build at all. GitHub Packages carries the same artifacts for anyone
who prefers it, and needs one.

```kotlin
// settings.gradle.kts
dependencyResolutionManagement {
    repositories {
        maven("https://raw.githubusercontent.com/yschimke/wear-m3-catalog/wear-compose-cmp-maven/")
        google()
        mavenCentral()
    }
}
```

```kotlin
// build.gradle.kts — a Kotlin Multiplatform module with a wasmJs target
kotlin {
    wasmJs { browser() }
    sourceSets.commonMain.dependencies {
        implementation("ee.schimke.wearcmp:wear-compose-material3:1.7.0-beta02-cmp01")
    }
}
```

These are Kotlin Multiplatform publications, so that one coordinate resolves the `-wasm-js` variant
by itself. Built against **Kotlin 2.4.10** and **Compose Multiplatform 1.12.0**; a consumer on a
different Kotlin needs a matching klib ABI, so bump both together.

`./gradlew publishToMavenLocal` and `./gradlew publishToBuildDir` (which writes the same repository
tree into `build/maven`) are the local equivalents.

The components read the watch they are drawing for from one composition local, because a browser is
not a watch and cannot answer for it:

```kotlin
import androidx.wear.compose.material3.*
import ee.schimke.wearcmp.port.*

CompositionLocalProvider(
    LocalWearDeviceConfiguration provides
        WearDeviceConfiguration(isScreenRound = true, screenWidthDp = 227)
) {
    MaterialTheme { Button(onClick = {}) { Text("Hello") } }
}
```

Everything else — round-vs-square layout, `isSmallScreen()` breakpoints, wrist orientation, the
24-hour clock — follows from that value. See
[`WearDeviceConfiguration`](modules/port-runtime/src/commonMain/kotlin/ee/schimke/wearcmp/port/WearDeviceConfiguration.kt).

### The other seams

The capabilities a browser has no equivalent of are interfaces with a composition local and a no-op
default, not stubs — so a host that IS portraying one can implement it and the components go on
calling the API they call on a watch:

| Seam | Provide | Default |
| --- | --- | --- |
| Ambient (always-on) mode | `LocalAmbientModeManager` (`AmbientModeManager`) | always interactive, never ticks |
| Screen reader / touch exploration | `LocalTouchExplorationEnabled` | `false` |
| Rotary haptics | `LocalRotaryHapticFeedback` (`RotaryHapticFeedback`) | `navigator.vibrate` |
| One-handed gestures | `LocalOneHandedGestureManager` (`OneHandedGestureManager`) | registers nothing |
| The clock | upstream's own `TimeSource` | the host's time zone, ticking on the minute |

Four of the platform bindings are real rather than stubs: `prefers-reduced-motion` for reduce
motion, `Intl.DateTimeFormat` for the 24-hour clock, the Screen Wake Lock API for `KeepScreenOn`,
and `navigator.vibrate` for haptics.

## Working on it

```bash
scripts/sync-upstream.sh     # pull the pinned release and regenerate  (network)
scripts/regenerate.sh        # regenerate from what is already vendored (no network)
scripts/check-generated.sh   # CI's check: committed output == pipeline output
./gradlew assemble           # build both targets
```

Use `-PcentralMirror=true` if Maven Central rate-limits you (HTTP 429 on a cold cache); it resolves
through Google's mirror of Central instead.

**Never edit `modules/*/src/commonMain` and expect it to survive** — it is deleted and rewritten on
every run. Changes go in `transform-rules.json` (mechanical, survives upstream churn) or in
`patches/` (surgical, cut by `tools/make_patch.py`). How to choose, and what to do when a patch
stops applying: [`docs/PIPELINE.md`](docs/PIPELINE.md).

## Why this branch has no history

`agent/wear-compose-cmp` starts from an empty tree on purpose. It shares no files with
`wear-m3-catalog`'s `main` — different build, different sources, different lifecycle — and starting
it as an orphan branch says so, rather than presenting 470 vendored files as a change to a catalog.
