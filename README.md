# wear-compose-cmp

**AndroidX Wear Compose, compiled for WebAssembly.**

A mechanical port of `androidx.wear.compose` — Material 3, Foundation and Material Core — from
Android to Compose Multiplatform, so that the Wear components can be rendered in a browser by the
[UI builder](https://github.com/yschimke/compose-preview-server) instead of only on a watch or an
emulator.

It is **generated, not forked**. Nothing here is a hand-maintained copy of AndroidX: the sources are
vendored from each release, transformed by rules, and patched only where a rule cannot reach. When
AndroidX cuts a release, the same pipeline runs again and the diff is the review.

```
upstream.json ──► tools/sync.py ──► upstream/ ──► tools/transform.py ──► modules/*/src/commonMain
   the pin        Google Maven      vendored        rules + patches         generated, committed
```

## What you get

| Artifact | Contents |
| --- | --- |
| `ee.schimke.wearcmp:wear-compose-material3` | 114 of 136 Material 3 files |
| `ee.schimke.wearcmp:wear-compose-foundation` | 64 of 69 Foundation files |
| `ee.schimke.wearcmp:wear-compose-material-core` | all 17 Material Core files |
| `ee.schimke.wearcmp:port-runtime` | the port's own seams — the `expect`s the three above compile against |

Targets: **wasmJs** (the point of the exercise) and **jvm** (which compiles an order of magnitude
faster and is how the port is checked). Version is `<upstream>-cmp<NN>` — `1.7.0-beta02-cmp01` is
the first port of AndroidX 1.7.0-beta02.

What is *not* in there, and why, is measured rather than described:
[`docs/ANDROID_SURFACE.md`](docs/ANDROID_SURFACE.md) is generated by the same run that produces the
sources. The short version is curved text, the two pickers, `TimeText`, dynamic colour and the
one-handed-gesture surface — 27 files of 222, each with a reason.

## Using it

```bash
./gradlew publishToMavenLocal      # ee.schimke.wearcmp:*:1.7.0-beta02-cmp01
```

```kotlin
// in the consuming build
implementation("ee.schimke.wearcmp:wear-compose-material3:1.7.0-beta02-cmp01")
```

The components read the watch they are drawing for from one composition local, because a browser is
not a watch and cannot answer for it:

```kotlin
CompositionLocalProvider(
    LocalWearDeviceConfiguration provides
        WearDeviceConfiguration(isScreenRound = true, screenWidthDp = 227)
) {
    MaterialTheme { Button(onClick = {}) { Text("Hello") } }
}
```

Everything else — round-vs-square layout, `isSmallScreen()` breakpoints, wrist orientation, the
24-hour clock — follows from that value. See
[`WearDeviceConfiguration`](modules/port-runtime/src/commonMain/kotlin/ee/schimke/wearcmp/port/WearDeviceConfiguration.kt).

## Working on it

```bash
scripts/sync-upstream.sh     # pull the pinned release and regenerate  (network)
scripts/regenerate.sh        # regenerate from what is already vendored (no network)
scripts/check-generated.sh   # CI's check: committed output == pipeline output
./gradlew assemble           # build both targets
```

Use `-PcentralMirror=true` if Maven Central rate-limits you (HTTP 429 on a cold cache); it resolves
through Google's mirror of Central instead.

**Never edit `modules/*/src/commonMain` and expect it to survive** — it is deleted and rewritten on
every run. Changes go in `transform-rules.json` (mechanical, survives upstream churn) or in
`patches/` (surgical, cut by `tools/make_patch.py`). How to choose, and what to do when a patch
stops applying: [`docs/PIPELINE.md`](docs/PIPELINE.md).

## Why this branch has no history

`agent/wear-compose-cmp` starts from an empty tree on purpose. It shares no files with
`wear-m3-catalog`'s `main` — different build, different sources, different lifecycle — and starting
it as an orphan branch says so, rather than presenting 470 vendored files as a change to a catalog.
